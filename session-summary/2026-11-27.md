## 4. Technical Learnings
- **Scans can carry a text layer.** eSCRIBE stamps "Attachment #1 Page N of 13 Report: CR_6544" on each page of an uploaded scan. Any "has text?" check has to go by text per page, not by whether any text exists.
- **Matching file names in route C works.** Firefox saves under the attachment title, and the `WANTED.md` title (the part before its parenthetical notes) matched all 12. Bound the search with `find ~/Downloads -maxdepth 1 -newermt '<last batch time>'`.
- **Key strings for checking content:** if a grep finds 0 hits, check the guess before suspecting the file. "18666" isn't in 9778 and "7218" isn't in 4785, yet both texts are the right document.
- **The word-per-line count is now 4 text files:** 286947, 295437, 9778 and 78486. 9739's flag went away when it became a scan. The cause is still unknown.
- **The two machines overlapped:** a civic-docs-index server session merged #28 (`WANTED.md` told dates) while this laptop session was editing the same file. That caused a stash-pop conflict, resolved by keeping the server's rows (`git checkout --ours`) and reapplying only the 9739 wording. **`CLAUDE.md` says not to run the repo from both machines at once:** confirm which machine is active before starting.
- **Commands that fail quietly:**
  - `gh pr create -q` isn't a valid flag, and with `| tail -1` it failed with no output. Don't pass `-q` to `gh pr` commands.
  - `git -C data/raw/private pull` refuses while the tree is dirty. Pull before running `--recheck` or the ingest.
- **Squash merges change the SHA.** `merge-base --is-ancestor <branch sha> origin/master` fails after a squash merge. Instead, check `git diff --stat <branch sha> <squash sha>` is empty.
